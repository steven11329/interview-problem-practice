# Remove Element 討論筆記

## 題目理解
- 要「原地」把陣列中不等於 `val` 的元素搬到前面 `k` 格，順序可以改變
- `k` 之後的內容不重要，回傳值 `k` 才是判題唯一在意的東西

## 踩過的 bug（`basic.ts` 雙指標交換法）
用左右夾擊、交換元素的方式實作時，一開始只寫了三個分支：

```ts
if (nums[lIndex] === val && nums[rIndex] !== val) {
  // 交換，兩指標都前進
} else if (nums[lIndex] !== val && nums[rIndex] === val) {
  lIndex++;
} else {
  rIndex--; // ← 這裡把兩種不同情況混在一起
}
```

`else` 同時吃掉了「兩者都是 val」跟「兩者都不是 val」兩種情況，但這兩種情況該做的事完全不同：
- 兩者都是 `val`：`rIndex--` 是對的，要繼續找右邊非 `val` 的元素來跟左邊交換
- 兩者都**不是** `val`：應該 `lIndex++`，把左邊已經合格的元素跳過；寫成 `rIndex--` 會讓右邊那個原本合法的元素被排除在計算範圍外，永遠不會被算進 `k`

**反例**：`nums = [1, 3, 2, 5], val = 2`
- 修正前：回傳 `k = 2`（錯，把 `5` 弄丟了）
- 修正後：回傳 `k = 3`（對，`1, 3, 5` 都不等於 `2`）

修正方式是把 `else` 拆成兩個明確分支：

```ts
} else if (nums[lIndex] === val && nums[rIndex] === val) {
  rIndex--;
} else {
  lIndex++;
}
```

另外，`basic.ts` 結尾用「掃描第一個等於 `val` 的 index 當作 `k`」，這隱含假設雙指標處理完後陣列一定是「前段全非 val、後段全 val」。上面的 bug 存在時這個假設不成立，掃描法就會跟著算錯；即使雙指標邏輯修正後假設成立，這段掃描本身也是多跑一次 O(n)，是可以省略的額外開銷。

## 複雜度分析
| | `basic.ts`（雙指標交換，修正後） | `improved.ts`（快慢指標） |
|---|---|---|
| 時間 | O(n)：主迴圈 O(n) + 結尾掃描 O(n)，相加仍是 O(n) | O(n)：單一迴圈跑完 |
| 額外空間 | O(1)：只有 `lIndex`、`rIndex` 兩個變數 | O(1)：只有 `k` 一個變數（`i` 是迴圈自帶） |
| 分支數 | 4 個分支，需要處理交換時的暫存邏輯 | 1 個條件判斷，沒有交換 |

兩者 Big-O 一樣，差別在常數因子與可讀性。

## 優化版解法（`improved.ts`）
```ts
function removeElement(nums: number[], val: number): number {
  let k = 0;

  for (let i = 0; i < nums.length; i++) {
    if (nums[i] !== val) {
      nums[k] = nums[i];
      k++;
    }
  }

  return k;
}
```
- `i`（快指標）負責掃過整個陣列一次
- `k`（慢指標）記錄「下一個要寫入的合格位置」
- 每次遇到 `nums[i] !== val`，就把它寫到 `nums[k]`，`k` 才前進；遇到 `val` 就單純跳過（連交換都不用做，因為不要求保留順序）
- 迴圈跑完 `k` 就是答案，不需要像 `basic.ts` 那樣事後再掃一次找 `val` 的位置

## 為什麼這版通常實測 mem 會比較低
- 少維護一個指標變數（沒有 `rIndex`），也不需要交換時「讀兩個位置、寫兩個位置」的暫存動作
- 少一段「事後掃描找 k」的迴圈，整體運算量更小
- 分支只有一個 if，對 V8 的 JIT 優化更友善

不過要注意：**LeetCode 判題頁上的 mem 數字本身雜訊很大**，同一份程式碼重複送出也可能有幾十 KB 的浮動。實務上影響最大的反而是送出去的程式碼裡有沒有殘留 debug 用的 `console.log` 或額外的自我測試呼叫（`basic.ts` 最初版本就有這個問題）——這些屬於多餘開銷，送出判題前應該清乾淨，往往比演算法細節的差異更明顯。

## Edge case 驗證
`k=${removeElement([], 2)}` → `0`
`k=${removeElement([1], 2)}` → `1`（沒有等於 `val` 的元素，兩版都要能正確回傳整個陣列長度）
