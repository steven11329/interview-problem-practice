# Merge Sorted Array 討論筆記

## 題目理解
- `nums1` 的長度規定是 `m + n`，前 `m` 格是有效資料，後面 `n` 格是佔位用的 `0`
- `m = 0` 代表 `nums1` 沒有任何有效資料，陣列裡的 `0` 只是為了湊出長度，不是真的資料
- 結果要「原地」存回 `nums1`，不能用 `return`

## 踩過的 bug
1. **陣列拿錯**：`else` 分支（`nums1[i1] > nums2[i2]` 時）誤寫成 `merged.push(nums1[i2])`，應該是 `nums2[i2]`。三個原始測試 case 剛好都沒走到這條路，沒被抓出來。
2. **重新賦值陣列參數沒有用**：
   ```ts
   function merge(nums1, ...) {
     nums1 = merged; // ❌ 只是讓函式內的區域變數改指向新陣列，外面呼叫者的陣列完全沒被動到
   }
   ```
   陣列參數傳進函式時，參照本身是「複製」進來的區域變數，重新賦值不會影響呼叫端。要嘛用迴圈把值一一寫回原陣列的每個格子（`nums1[i] = merged[i]`），要嘛直接原地修改（見下方 O(1) 解法）。

## 兩種解法比較
| | 從前面比、堆進新陣列 | 從尾端往前寫（O(1) 空間） |
|---|---|---|
| 額外空間 | O(m+n)（`merged` 陣列） | O(1) |
| 時間 | O(m+n)，但因為多一輪複製回 `nums1`，實際跑 `2*(m+n)`（Big-O 還是 O(m+n)，常數被忽略） | O(m+n)，一輪就完成 |
| 關鍵原因 | 從頭寫會蓋到 `nums1` 裡還沒讀過的原始資料，所以沒辦法直接原地覆寫 | 寫入位置 `i` 永遠 ≥ 讀取指標 `i1`、`i2`，不會蓋到還沒讀的資料 |

**為什麼不能「從頭插入」做到 O(1) 空間**：從頭寫，寫入位置很容易追上、甚至超過還沒讀的資料，會覆蓋掉。硬要做的話得先把後面元素往右搬出空位（像手動插入排序陣列），空間可以是 O(1)，但時間會退化到 O((m+n)²)。

## O(1) 空間解法（`improved.ts`）
```ts
function merge(nums1: number[], m: number, nums2: number[], n: number): void {
  let i1 = m - 1;
  let i2 = n - 1;
  let i = m + n - 1;

  while (i2 >= 0) {
    if (i1 >= 0 && nums1[i1] > nums2[i2]) {
      nums1[i] = nums1[i1];
      i1--;
    } else {
      nums1[i] = nums2[i2];
      i2--;
    }
    i--;
  }
}
```
三個指標從尾端往前走，每次把兩邊目前較大的值填到 `nums1` 的尾端空位，`i2` 走完就結束（剩下的 `nums1` 元素本來就已經在對的位置）。

## 換成 Java 的話
- 邏輯完全一樣（三指標從尾端往前），因為 Java 陣列也是傳參考，原地改格子一樣有效
- Java 的 `int[]` 長度固定，`nums1.length` 一定得是 `m+n`，這點題目本身就保證了（不像 TS 陣列可以自動擴長矇混過去）
- 如果題目變體給的 `nums1` 沒有預留 `n` 格空間（例如就是 `[1,2,3]` 長度剛好等於 `m`），O(1) 原地解法就完全不能用了——沒有多餘空間可以寫。這時候只能退回開一個 buffer array（或直接回傳新陣列），空間退回 O(m+n)。
